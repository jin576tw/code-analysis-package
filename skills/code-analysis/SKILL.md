# Code Analysis

## 目標

依本次要求，從**目前原始碼**產出使用者需要的分析文件；每個重要主張可追溯到來源，範圍內行為無未標示的缺漏。
執行順序、工具與批次由你依任務判斷；以下邊界與完成判準才是約束。

## 邊界

- **優先序**：本次使用者要求 > 專案設定 > 本 skill 預設。專案設定分工：`CLAUDE.md`／`AGENTS.md` 定安全與工作區邊界，`.analysis-profile.md` 定來源導覽與交付位置／清單，模板定文件內部章節；同一欄位真正衝突時才詢問，未解前該交付物列為 `blocked`。profile 格式見 [profile 模板](assets/analysis-profile.template.md)；沒有 profile 時從建置檔、路由／job 定義辨識必要資訊即可。
- **事實界線**：AS-IS 以目前來源確認；記憶、舊文件、註解與命名只作導航。區分 `code-derived`／`inferred`／`business-input`，以及 AS-IS／核准需求／提案。未查證的內容列為未知，不寫成事實。
- **不做**：修改產品程式碼、提出 TO-BE、發布或覆寫外部文件、產出未要求的文件或空殼文件、建立全專案索引、逐階段評分。使用者要求的文件修正直接做。
- **只在必要時問**：入口歧義、需求衝突或必須擴大範圍；其他部分持續完成，不在里程碑停下詢問。
- **Mock／重建畫面**只能標 `simulation`，不算執行證據。
- **平台中立**：使用當前平台可用的讀檔、搜尋、執行與子代理工具，不依賴特定工具名稱。

## 完成判準

1. 交付物與使用者要求（或 profile／模板）的文件、章節一致；不適用的必要章節寫明理由。
2. 每個重要主張有 路徑＋符號／行號；同一事實只記一次，文件以證據 ID 引用（[分析模板](assets/analysis.template.md)）。
3. 範圍內的觸發條件、正常／失敗／空值／未命中分支、狀態變化與副作用已寫入，或列為 gap。
4. 已完成雙向核對：文件→來源（主張正確）與來源／需求→文件（沒有漏寫）。
5. 未知、缺少的執行證據與其影響列在限制段落。

## 審查與狀態

- **預設自查**：自行完成雙向核對，狀態 `self_reviewed`。
- **使用者要求 `verified` 或獨立審查**：若環境允許，交一個獨立 Reviewer 子代理（不給 Maker 結論當查證依據）；修補後只複審已修項目與其相依位置。無法使用子代理時維持 `self_reviewed` 並說明。
- 只有獨立 Reviewer 對**目前交付版本**完成雙向核對、verdict 為 pass、無未解阻擋問題且必要證據齊全，才可標 `verified`；審查後再改交付物或來源即失去 `verified`。其餘為 `self_reviewed` 或 `blocked`。
- 缺少影響正確性或交付要求的來源／執行證據：`blocked`，其他獨立部分照常交付。使用者接受的偏差寫在限制。
- 摘要回報：文件位置、覆蓋範圍、狀態、未解事項。
