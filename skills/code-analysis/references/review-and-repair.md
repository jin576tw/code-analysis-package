# 審查判準

## 雙向核對要達到的結果

- **文件→來源**：範圍內可驗證主張（含圖、表、範例、附錄）與來源一致；相同事實查一次，但標出所有受影響位置。
- **來源／需求→文件**：自行從來源與需求枚舉可達分支、失敗／空值／未命中、欄位契約、狀態與副作用，與文件比對；不以 Maker 的覆蓋表作唯一清單。需求無對應程式碼時標現況差異，不刪除。
- 大範圍可分批核對，但未核對的部分要列出，不宣稱全部通過。

## 獨立審查（僅在使用者要求 verified 或獨立審查時）

- Reviewer 輸入：本次要求與範圍、文件、證據、來源位置、本檔。自行讀原始碼；只寫 `REVIEW.md`，不改 Maker 文件。
- 一次交出完整問題集合，不抽樣、不設最低缺陷數、不發暫定 PASS。
- Maker 集中修補完整集合；複審只核對已修項目與其相依位置，並區分「未修好／修補引入」。仍有阻擋問題時停止自動迴圈，交付問題與建議。

## 阻擋問題

- 錯誤的入口、資料來源、核心行為、交易、權限或對外契約。
- 必須覆蓋的要求或重要正常／例外行為缺漏。
- 推論寫成事實、simulation 當真實驗證、重要主張無證據。
- 必要執行／交付證據缺失。

文句改善與額外背景是非阻擋建議，不觸發修補迴圈。未定義計數方式的數字規則，列一次歧義即可。

## 最小 REVIEW.md

只在獨立審查或使用者要求審查紀錄時產出。問題表引用證據 ID，不重抄來源位置。

```markdown
# Review
- review_kind: independent | self
- verdict: pass | fail | incomplete
- reviewed_files: 文件清單
- 已核對／未核對範圍：
- runtime_evidence: static | observed | simulation | missing（按項目列）

| ID | 阻擋？ | 問題與影響 | 證據 ID | 文件位置 | 修法／關閉證據 |
|---|---|---|---|---|---|

## 非阻擋建議
```

無問題就寫「無」。
