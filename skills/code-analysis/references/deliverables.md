# 文件選擇與交付

## 輸出要求優先

先沿用使用者提供的文件、章節與命名契約；將每個必須覆蓋的要求列在文件範圍段落，映射到證據／行為表與文件位置。
未提供契約時，依目標和讀者建立最小清單並說明假設，不要求使用者先手寫 JSON 才能工作。
必填章節不得默默刪除；不適用時提供理由。額外背景和無關功能不為了「完整」而擴寫。

預設輸出至專案設定的 docs 位置；未指定時用 `.analysis/docs/<feature>/`。
預設 REVIEW.md 與 run.json 放在同一輸出目錄；多次分析要保留歷史時才用 `_run/<run-id>/`。每次新分析使用不同 run-id，續跑沿用原 run。
範圍、快照與必要審查紀錄不得因清理暫存而遺失。

## 預設直接形成交付物

預設只寫 `ANALYSIS.md` 或使用者指定文件。無模板時採最小骨架：

1. 功能與範圍：入口、角色、輸入與產出。
2. 行為：正常／替代／失敗流程、前置條件與副作用。
3. 相關技術影響：只有本次需要的資料、API、交易或 UI 細節。
4. 來源與限制：證據 ID／位置及待確認項目。

不先產出九份中間文件再重寫成一份；collectors 的結果直接進共用證據。
文件份數減少仍須覆蓋本次要求的所有重要行為。

## 按交付要求選用文件

下表是可選交付物，不是每次必跑的階段清單。需要多份文件時，先確定適用文件與其覆蓋要求：

| 文件 | 必要內容 |
|---|---|
| DEPENDENCIES.md | 可達呼叫、資料讀寫、上游控制資料、外部邊界 |
| VARIABLE-LIST.md | 跨層欄位、型別、轉換、驗證、常數與狀態 |
| ERD.md | 儲存實體、關係依據、基數與欄位映射 |
| FUNCTION-LIST.md | 相關函式簽章、責任、呼叫、例外與副作用 |
| FLOWCHART.md | 正常與失敗分支、狀態、交易與跨系統互動 |
| BUSINESS-RULES.md | 有來源的條件、行為、影響與具體驗收情境 |
| UI-VERIFY.md（UI 適用） | 操作／狀態覆蓋、靜態證據與執行證據分類；無實測不可宣稱已測 |
| SD.md | 技術責任、資料流、介面、交易、例外與限制 |
| API-CONTRACT.md（API 適用） | 自成一體的 request／response、繼承欄位、認證與錯誤契約 |
| SA.md | 面向業務／PM／QA 的能力、操作、輸出、例外與 Given-When-Then |

不適用的文件記在範圍清單，不生成空殼；使用者明確要求固定文件集時，保留對應文件並標示不適用理由。
產出邏輯順序是相依與欄位／模型／函式 → 流程 → 規則 → SD／SA／契約，無逐文件評分迴圈。
只有找到入口、資料表或主流程矛盾時，先修正共同證據再繼續依賴文件。

## 讀者與事實界線

- SA 使用真實畫面標籤、使用者操作及可觀察結果；技術引用放證據註記，避免正文塞滿類名。
- SD 保留責任、I/O、交易與例外細節；不能從程式推導當年設計意圖時標推論。
- API 每個介面列完整適用欄位，不用「同上」代替契約。
- AS-IS 與 approved requirement／proposed design 分開；分析現況不主動生成目標架構。
- Mermaid 用英文 ID 與清楚顯示文字，判斷節點具條件；圖、表、正文對同一行為引用相同證據。

## 修改與衍生文件

只改空白、字型或圖形位置而未變更標籤、節點、邊、值與條件時，走呈現檢查。
只比較節點／邊集合相同不足以證明圖語意不變；還須比較文字、方向、分組及條件。
技術內容變更會使舊審查失效。若文件嵌入圖片／匯出檔，記錄相依關係並確認一併更新，或在交付時揭露尚未同步部分。
轉檔／發布只在要求時執行，使用目標環境適合的文件工具；本 skill 不內建 PDF／DOCX 產生器。
