# 按需分析方法

先讀範圍、目標入口及目前來源。以程式碼確認 AS-IS；註解、命名與舊分析僅提供線索。
需求的「應該」不會自動成為程式的「現在會」。無需求佐證的設計理由只可列推論。

## 相依與資料來源

- 沿可達呼叫追查 UI／API／Job → 服務 → query／mapper → 實體儲存與外部服務；imports 或注入存在不代表一定執行。
- 找共享 SQL 片段、動態查詢、生成與自訂 mapper、設定註冊和實際入口綁定。紀錄讀／寫操作、資料源與交易管理器。
- 只在上游資料會控制本功能條件或結果時反查提供者；避免為全域共用表建立全專案關係索引。遇循環停止並標示，跨出範圍先說明影響。
- 關係分為直接呼叫／共享資源、推論關係、業務流程關係；呼叫圖本身不能證明人員審批順序。

## 欄位、模型與函式

- 核對 UI → request／DTO → model → column 的型別、必填、預設、驗證、轉換、空值與回傳方式；保留繼承欄位。
- 常數值到定義處核對；常數名稱不等於已證實業務語意。完整與部分更新、null 覆寫、反射 getter 不匹配均需追到實際操作。
- ERD 區分 DB 強制外鍵與應用程式邏輯關聯，基數需有來源；不因命名像 ID 就補上一條關聯。
- 函式保留完整簽章、呼叫者、輸入輸出、副作用、例外與交易屬性；跳過對理解無幫助的逐行 accessor 清單。

## 流程、規則與交易

- 先逐條列出觸發條件、分支結果、例外處理與狀態變化，再畫 Mermaid／寫 Given-When-Then。
- 找出未命中、空集合、空值、重複操作、部分失敗、錯誤被吞掉、成功 HTTP 狀態包住失敗結果等實際可達路徑。
- 核對交易宣告、代理／呼叫邊界、propagation、不同 manager／datasource、async listener、chunk commit；不從單一 annotation 推定跨系統原子性。
- 區分記憶體、已送出參數、資料庫持久化及外部系統產物。參數相同不代表外部生成的 PDF 內容相同。
- 業務規則描述「條件 → 系統行為 → 可觀察結果」；商業理由若無來源，標未知而非補故事。

## SQL 或可執行邏輯重建（僅要求此產出時）

1. 直接讀原始 predicate／SQL 建構邏輯，不從 SA／ERD 的業務摘要反推運算子。
2. 每張主表、JOIN 表、EXISTS／IN 子查詢表分別核對 ORM／schema 及 physical naming strategy。
3. 保留括號、量詞、NULL 三值邏輯、null-skip、獨立上下界、集合與多列語意；不得把可各自略過的條件直接合成 BETWEEN。
4. 檢查多筆／無匹配／單邊界等可能使「看似等價」失效的資料形狀。
5. 靜態核對過的 SQL 只稱「依來源重建、未執行」。只有在獲准環境實際執行後，才宣稱已驗證可執行。

## UI／反應式框架

- 從模板與事件綁定追實際 handler、欄位條件、可見／禁用、載入／空／錯誤／成功狀態及下載。
- 追生命週期、引用與複製、深淺 watcher、更新／emit 契約及資料重新指派；能從程式解出的兩條分支都寫清楚。
- 獨立建立「操作 × 前置狀態 × 結果」表，對照文件以找漏寫。需要畫面重建時用它暴露缺漏，但不把重建結果當真實運作證明。
- 真實瀏覽器驗證範圍見 [執行期驗證](runtime-verification.md)。

## API／外部服務

- 核對 route、verb、認證條件、request／response 全部適用欄位、繼承、驗證、錯誤與副作用。
- 缺少被呼叫服務 repo 時，先查 OpenAPI／WSDL／client source／本地依賴套件介面；JVM 可查 JAR／javap。只取得契約就只宣稱契約已確認。
- 記錄 timeout、retry、冪等與回應編碼的已知證據，不假設 SOAP 回應是純 XML、不假設 mock 的回應格式等於真實服務。

## Batch

- 確認 job 定義、參數、step 順序、條件分支、動態啟動的子 job 及排程來源。
- 追 tasklet 或 reader → processor → writer、paging／chunk、提交間隔、失敗重啟／重試／skip、狀態表與重複執行效果。
- 排程名稱不能證明實際觸發方式；查上游 job chain 和設定。無部署排程證據時只描述程式支援的觸發方式。
