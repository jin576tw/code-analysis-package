# UI 與執行期證據

先分開三個問題：文件是否覆蓋所有相關狀態、主張是否需要真實執行確認、交付格式是否需要圖片。

| 情況 | 行動 |
|---|---|
| 非 UI | 不做瀏覽器驗證；API／批次若有重要執行主張仍按證據需求判斷 |
| 程式可確定條件與結果 | 靜態追查並寫清分支，不為知道當下是哪條分支而要求人點畫面 |
| 交付需要實際布局、下載、時序或外部整合結果 | 有獲准可用環境就驗證；沒有則標明該項缺少執行證據 |
| 只要求 AS-IS 程式機制說明 | 可以交付已證實的靜態行為與限制，不因程式含 JavaScript／AJAX 就強制 E2E |
| 交付明確要求畫面圖 | 優先使用對應版本的獲准真實畫面；不能取得時，依需求以 simulation 示意或列出缺少圖片 |

有瀏覽器訊號不等於所有主張都必須實測。若重要的交付主張只能靠執行確認，未取得環境時該項必須 blocked，不能用 Mock 通過。
截圖是說明素材或觀察證據，其角色必須標示；一張示意圖本身不會改變執行驗證判定。

使用現成驗證環境與工具，不在每個功能目錄重裝瀏覽器依賴。記錄執行場景、版本、預期、觀察、結果與檔案位置，不記錄帳密／個資。
以真實資料未經測試的外部輸出，不得宣稱內容相同、格式正確或整合成功。Generated HTML、Mock API、假資料與重建截圖一律標 `simulation`。
不要在修補時重跑未受影響的執行場景；靜態複審仍核對完整交付範圍。

圖片／圖表修改後，檢查正文描述、圖上文字與嵌入位置一致。若素材排除於本次範圍而造成可見落差，揭露影響與待辦，不默認已同步。
